## 🧭 重要設計決策與理由（給未來的自己／新 AI）

### 1. 為什麼採「零維護設計」？
教團人力流動大，專案負責人擔心交接後無人更新。
→ **原則：寧可少寫，也不要寫會過期的資訊。**

### 2. 為什麼不列「常態活動時間表」？
朝山原本沒有固定日期（各區會自行號召，想去就去），列假日期等於製造錯誤資訊。
後來教團確認有年度三次「觀音三會」，才改為現在的設計。

### 3. 為什麼不寫「全年開放」？
道場並非全年開放，寫了會讓信眾撲空。
→ 改為純鼓勵語氣（「發心，就是啟程」），實務細節導向「事先聯繫」。

### 4. 為什麼不嵌入臉書？
八個社群中**七個是「社團(Group)」**，Meta 不提供社團嵌入功能（僅粉專可嵌）。
例外：新北 B 區是粉專（網址 /093newtaipeiB），理論上可嵌入，但只有一個會破壞版面一致性。
→ 曾改用連結卡片，**但 2026-08-04 已全部移除**，理由見下方第 7 點。

### 5. 為什麼日期不自動農曆換算？
2026 三個日期都在週末（日／六／日），但無法確定規則是「往後推」或「取最近週末」，
且教團可能因法會排程調整。**自動算錯比不算更糟。**
→ 共識：**程式算農曆給管理員「參考」，最終日期由人決定。**

### 6. 為什麼日期判斷用瀏覽器時間？
若用伺服器時間，靜態部署到 Netlify 後日期會凍結在建置那天。
→ 用 client component + isMounted 判斷，避免 hydration 閃爍。

### 7. 為什麼各地講堂只放官網連結，不列地址電話？（2026-08-04 決議）
查到教團官網有完整名單（16 講堂＋3 道場，含電話、傳真、地址），但**刻意不複製**。

**發現的問題：**
- 該頁最後更新為 **2020-12-23，已 5 年多未動**
- 台東中心：電話、傳真、地址**全部空白**
- 新竹共修處：註記「搬遷裝修中，請聯繫桃園講堂」— 是 2020 年的狀態
- 桃園講堂地址缺行政區
- 官網有**兩套並行分類**：區會（10 個，含新北市B區）vs 講堂（16 個實體場地），
  我們原本的名單混用了兩者
- 16 個講堂只有 6 個有朝山社團，全列會有一半顯示「連結準備中」，版面很空

**決策：**只放一個連結到官網，本站不維護第二份。
> 講堂會搬遷、電話會變、共修處會增減。
> 抄一份到本站，遲早變成過期的錯誤資訊，害信眾撲空。
> 交給教團官網統一維護，我們永遠不需要更新。

**用戶原話**：「雖然會跳出這個網頁但我覺得無須更新會更好。」
→ 這是「零維護設計」原則最徹底的一次實踐。

**⚠️ 給未來的自己／新 AI：不要好心把講堂地址加回來。** 這是刻意的取捨。

### 8. 為什麼活動回顧可以「全文照抄」，講堂資訊卻不行？（2026-08-04）
關鍵差別在於**內容會不會過期**：

| 類型 | 會過期嗎 | 做法 |
|---|---|---|
| 講堂地址、電話 | ✅ 會（會搬遷、會改號） | 只放官網連結 |
| 活動回顧文章 | ❌ 不會（歷史紀錄） | 全文收錄，放心保留 |

2026 年發生的事，永遠是 2026 年的事。
→ 所以回顧文章採「摘要＋展開全文」，不必擔心變成錯誤資訊。

**展開方式用 HTML 原生 `<details>`**，不寫 JavaScript：
瀏覽器自帶三角形、手機可用、無障礙支援，而且**永遠不會壞**。

### 9. 為什麼官網的照片一定要下載，不能直接連？（2026-08-04）
教團官網文章內的圖片網址長這樣：
```
https://www.ljm.org.tw/dharmapala/files/image001.jpg   ← Word 貼上的通用檔名
https://www.ljm.org.tw/dharmapala/files/image003.jpg
```
對照右側「相關消息」的封面圖：
```
files/202604cover_506811037_thumb.jpg   ← 有日期＋亂數，唯一
```

**全站文章共用同一個 `files/` 資料夾**，而內文圖是 Word 匯出的通用檔名。
→ 下一篇文章只要也從 Word 貼圖，就會**把 image001.jpg 覆蓋掉**。
→ 到時我們的卡片會顯示完全不相干的照片，而且沒人會發現。

**鐵則：官網照片一律 `curl` 下載到 `public/images/`，永遠不要直連。**

  - 問題原因：`useRef` 的值在 HMR 時會被重置，而 `useState` 的值會被 React Fast Refresh 保留
  - 解決方案：將 `hasEverTransitioned` 從 `useRef` 改為 `useState`
  - 新增 `isMounted` 狀態追蹤組件是否已掛載
  - 只有在 `isMounted && hasEverTransitioned` 時才播放動畫
